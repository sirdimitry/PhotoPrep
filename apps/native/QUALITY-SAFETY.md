# Приёмка качества и ресурсов

29.10.2026. Требования, а не заявление о готовности.

## Качество удаления логотипа

До оптимизации Core ML зафиксировать Python reference. Синтетический набор из
`Tools/quality_benchmark.py` содержит оригинал без надписи, наложенную тестовую
надпись и маску. Личные фотографии не используются. Случаи: ровный цвет, градиент,
повторяемая фактура, тонкие линии, контрастная граница, край кадра, полупрозрачный
знак, полупрозрачный исходник. Отдельно нужны разрешённые реальные фото: кирпич,
ткань, волосы/лицо, листва, стены/тени, большие и разрозненные логотипы.

Для каждого движка сохранить output, SHA256 входов/модели, manifest, время загрузки,
первого и повторных проходов, peak RSS отдельного процесса. RGB MAE внутри маски
на известном чистом фоне — ориентир, не автоматическое доказательство красоты.
Проверять 100%/200%: остатки букв, цветные ореолы, разрыв линий/перспективы,
неверный свет, размытие и повторяющиеся пятна. Слепое сравнение Python/Core ML
на одинаковой маске; нерешённый артефакт в типовом случае блокирует объявление паритета.

Строгие gates: ноль изменённых RGBA-пикселей с coverage=0, ноль изменённых alpha,
неизменный SHA256 оригинала; finite output/валидная shape, edge/empty/erase masks,
одиночный штрих, несколько/смешанные проходы, отмена/ошибка без commit,
открытие сессии и replay. Два разных AI-движка не обязаны совпадать внутри маски.

Начинать с FP32 reference. FP16, quantization, другой контекст, тайлы и compute units
принимаются только после сравнения качества и памяти. Независимые тайлы могут
создавать швы и неверный контекст; не включать такой fallback автоматически.

## Политика памяти и отказов

* До decode проверять заголовок, положительные размеры, безопасное умножение,
  число кадров/лимиты; неизвестный размер отклонять. Повторять проверки после decode.
* Preview — ImageIO thumbnail с применённой ориентацией, максимум 2048 px;
  одна очередь decode, без десятков Task на каждое движение выделения.
* Общий учёт активных буферов, кэшей и резерва модели. Бюджет ограничен долей RAM
  и доступной памятью, с запасом для ОС; число пикселей само по себе недостаточно.
  Бюджет модели задаётся по измеренному пику, не размеру файла весов.
* Предварительная политика: app budget min(2 GiB, physicalRAM/4), cache внутри него
  min(128 MiB, budget/8); минимум 2 GiB системного резерва. Для старта тяжёлой
  задачи проверять available memory и projected peak. Это исходная консервативная
  политика для LaMa/MI-GAN, не измеренная гарантия и не допуск SDXL.
* Только одна тяжёлая модель; unload перед сменой. Не держать историю полных
  изображений; рецепты + bounded LRU. Inference/composite работают с ROI,
  не создают full-frame float32 RGB. Autoreleasepool на файл/проход.
* Warning: очистка кэшей и запрет новых тяжёлых задач; critical: отмена очереди,
  отбрасывание поздних результатов и остановка worker с сохранением рецепта.
* Native worker изолирует crash движка, IPC ограничивает размеры и валидирует
  сообщения. Watchdog памяти/таймаута обязателен до реального inference. Лимит
  RSS/pressure — защитный механизм, не жёсткая квота всей GPU/unified memory.
* Предсказание Core ML может не остановиться мгновенно. JobID/generation/source
  identity/recipe revision должны совпадать при commit; cancel делает результат
  недействительным сразу. UI не ждёт синхронно на главном потоке.
* Проверять свободный диск до staging/compile/download; атомарная запись и 0600/0700.
  Проверять hashes моделей, доверенную структуру пакета, symlinks и границы путей.
  Без загрузки исполняемого кода модели, без сетевых фото/масок/путей.

## Ресурсная приёмка перед Native-релизом

На реальных 8/16/24+ GiB Mac: cold/repeat, 1/12/40 MP, 50 последовательных проходов,
100 фото в очереди, mixed models, быстрые переключения фото, повреждённые файлы,
forced worker exit, cancel во время load/predict/export, заполненный диск,
warning/critical pressure и закрытие окна во время задачи. Не доводить рабочий Mac
пользователя до OOM ради теста; сначала инъекции ограниченного бюджета/pressure.

Записывать peak physical footprint и RSS, p50/p95 по фазам, swap/pressure,
восстановление после ошибки и объём памяти после выгрузки. RSS не включает всю
память GPU/драйверов. Не публиковать неподтверждённые цифры скорости и обещание
«не может уронить систему». Не выпускать, если нарушен бюджет или длинная серия
показывает устойчивый рост. Порог задержки задаётся после reference-замеров,
регрессии сравниваются на том же Mac/OS/model/compute units.

# E1.6 — файловый путь сессий, dirty state и доступ

**Дата:** 31.10.2026  
**Ветка:** `e1.6/session-ui`, от E1.5 `6287e54`.  
**Коммиты:** `dedb5e2` (file picker/access/dirty/off-main), отчёт/статус — этот коммит.

Python, окружение, веса и пользовательские данные не менялись. Новых функций редактора/моделей/FP16/формата 8 нет.

## 1. Выбор конкретного `.photoprep.json`

* «Открыть набор…» снова выбирает **файл**, не папку; список файлов показывает оба набора, пользователь выбирает конкретный.
* Если для sandbox-доступа к фотографиям нужна папка, после выбора файла появляется **отдельный** folder picker с объяснением «Разрешите доступ к папке с фотографиями этого набора».
* Отмена folder picker не меняет текущий документ.
* При нескольких наборах приложение больше не выбирает первый файл молча.

## 2. Access/incomplete

* `SessionCodec` больше не пропускает отсутствующие фото: запись остаётся в `SessionPhoto` с `sourceMissing`, `skipped` считается.
* `openSession` загружает документ и пробует прочитать все источники. Если доступны не все:
  * без folder scope — запрашивает отдельный доступ;
  * после доступа, если фото всё ещё недоступны/отсутствуют — `session_incomplete`, документ **не применяется**, предыдущий остаётся;
  * частично загруженный набор не становится «успешным пустым» и не перезаписывается.
* `SessionCodec.save` отказывает `session_incomplete`, если есть missing source.
* Read-only документ сохраняет masks/passes/crop/logo в state и блокирует process/save.

## 3. Dirty state

Добавлен `isDirty`:

* `false` после успешного open/save/new;
* `true` после добавления/удаления фото, stroke/clear, pass, undo pass, rebase/reset;
* наличие проходов само по себе **не** делает документ dirty: открытый сохранённый набор с passes остаётся `isDirty=false`;
* ошибка сохранения не сбрасывает dirty;
* UI использует dirty для Open/New/Close/Cmd+Q.

## 4. Unsaved protection

* `confirmUnsaved` — три действия: **Сохранить / Не сохранять / Отмена**.
* Open/New: Save открывает save panel и прерывает текущее действие; Discard продолжает; Cancel ничего не меняет.
* Close guard (`windowShouldClose`) использует те же три действия; Save оставляет окно открытым до завершения save panel.
* `applicationShouldTerminate` для Cmd+Q использует тот же guard; Save отменяет завершение, Discard разрешает, Cancel отменяет.
* Save failure не разрешает закрытие/потерю правок.

## 5. Off-main session I/O

* `SessionCodec.load` выполняется в `Task.detached`; MainActor получает только готовый Sendable document.
* `SessionCodec.save` атомарная запись выполняется в `Task.detached`; dirty снимается только после успеха.
* Новый документ применяется только после успешной подготовки и проверки generation; ошибка/отмена открытия сохраняет предыдущий.
* `openSession` больше не ждёт `importBusy` циклом 60 s; использует decoder напрямую и generation/cancellation.

## 6. Python-контракт

Исправлено/проверено:

* `edits:null` → пустые edits;
* schema 1 без edits;
* абсолютный `selected` и абсолютные пути фото;
* относительные пути и missing sources сохраняются как записи;
* `strokes` отсутствует → пустая маска, passes/crop/logo разбираются;
* `passes: []`, `pass_models: []`, `crop:null`, `logo:null` принимаются;
* strict bool/целые/channel types;
* crop/logo параметры сохраняются полностью.

## 8. Реальный UI

* File picker теперь показывает конкретные `.photoprep.json` и фото, а не выбирает папку (screenshot).
* Попытка открыть конкретный набор в реальном UI была остановлена системным **memory pressure warning**: приложение показало «Загрузка остановлена: системе нужна память…» и не загружало документ. Это защита от OOM, не обход pressure.
* Поэтому полный UI open → save as → close → reopen на подписанном sandbox-приложении **не завершён**; dirty/Open/New/Close/Cmd+Q ручные сценарии также не подтверждены.
* Folder scope и read-write entitlement добавлены; внешние фото требуют выбора папки; end-to-end не закрыт.

## 9. Незакрытые пункты

* Реальный UI session open/save/reopen под sandbox не принят из-за memory pressure; нужен чистый прогон при normal pressure.
* Dirty/Save/Don't Save/Cancel для Open/New/Close/Cmd+Q проверены кодом, не полным UI.
* Быстрое A→B и switch during replay не проверены UI.
* Внешняя папка фото и отказ доступа не проверены end-to-end.
* Interrupted save проверен как no-overwrite/atomic, не kill посреди rename.
* 5 mask-пикселей/sub-LSB RGB остаются ограничением; паритет не заявлен.
* Нет native 40 Мп/8–16 GiB/Intel/macOS14; worker не XPC.

## Итог

Файловый путь теперь выбирает конкретный документ; папка запрашивается отдельно и только для доступа к фото. Неполный/недоступный набор не применяется как успешный и не перезаписывается. Dirty state основан на ревизии/сравнении, а не на наличии passes; Open/New/Close/Cmd+Q используют Save/Discard/Cancel. JSON load/save вынесены с MainActor; generation защищает от поздних документов. Python-контракт расширен отрицательными случаями.

Реальный UI-приёмка сессий остаётся незакрытой: memory pressure корректно остановил загрузку, и я не стал обходить защиту. Это главный оставшийся пункт.

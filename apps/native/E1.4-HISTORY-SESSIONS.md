## Часть A. Исправления истории и кэша

### A.1. Ключ кэша и modelID

Ключ результата больше не `path#index`. Он включает:

* **SourceIdentity**: `sha256`, `size`, `mtimeNS`;
* **идентичность последовательности проходов**: UUID каждого pass + modelID + fingerprint штрихов;
* индекс прохода.

`PixelCache` хранит значения только по такому ключу. Изменение исходника или замена/undo pass даёт другой ключ; старый результат не используется.

`RetouchPass` теперь содержит `modelID` (по умолчанию `"lama"`). Replay вызывает `modelURL(for: pass.modelID)`; неизвестная модель — ошибка, а не fallback на текущую. Новый проход сохраняет `"lama"`.

### A.2. SourceIdentity lifecycle

* При выборе фото маска/проходы загружаются, но кэш проверяется **после** capture SourceIdentity.
* Если identity не совпала с сохранённой в `PhotoEditState`, проходы/маска/result сбрасываются, cache очищается, выставляется `source_changed`; старая картинка не показывается.
* Перед process/replay identity перехватывается снова; при изменении commit невозможен.
- Regression self-test: coffee pass → cache present → файл изменён → switch away/back → result/passCount cleared, `error=source_changed`:

```json
{"cacheWasPresent": true, "sourceChangeCleared": true, "error": "source_changed", "passCount": 0}
```

### A.3. Undo pass и уточнение

`undoLastPass` теперь формирует:

```text
removedPass.strokes + currentRefinement.strokes
```

в этом порядке; текущие уточняющие штрихи не теряются. `passCount` уменьшается на 1, result — предыдущий pass (или nil), маска содержит удалённый pass + текущее уточнение.

Self-test: `undoOrdered=yes`, `passCountAfterUndo=1`.

### A.4. Lifecycle восстановления

* `InferenceWorkerClient.cancelAndWait()` — SIGTERM→SIGKILL→wait для switch/close.
* `cancelRetouch(wait:)`; switch/close ждут worker; активный job не очищается новым job.
* `startRestoreIfNeeded` очищает activeID/busy/task/phase **до** commit guard; при смене фото/устаревшем результате commit не выполняется, но состояние не остаётся занятым.
* Commit требует: активный jobID, generation, mask/edit revision, selected URL, отсутствие cancellation, неизменную SourceIdentity и неизменившееся число рецептов.
* `replayPasses` применяет общий `ResourcePolicy.admitRetouch` (app + worker + buffers).
* `syncCurrentResultWithCache` сбрасывает `resultImage`/display, если LRU вытеснил текущий ключ; один сильный reference display не обходит budget.

### A.5. Регрессии и реальный UI

* process → refinement → undo pass: `undoOrdered=yes`.
* undo pass → другой проход: ключ включает новые pass UUID/model/fingerprint; старый кэш не используется (код + cache key).
* source change при наличии кэша: self-test/JSON выше.
* eviction → replay: `pixelCache.clear()` + `restoreCurrentResult()` → `replayRestored=true`.
* switch photo: `switchKept=true`.
* cancel во время pending mask: `cancelKeptMask=yes`.
* 2 больших фото с вытеснением/восстановлением — **не выполнено** (см. ограничения).

**Реальный UI:** два прохода coffee, pass count **1 → 2**, затем уточняющий штрих и Undo Pass → pass count **1**, маска вернулась в canvas. Screenshot: `work/e1.4-artifacts/e1.4-undopass.png` (если сохранён). Переключение фото через NSOpenPanel проверено в E1.2; для E1.4 state switch проверен self-test.

## Часть B. Сессии `.photoprep.json`

### B.1. Reader схем 1–7

`SessionCodec.load`:

* проверяет `format="PhotoPrep"`, `version` 1–7, размер ≤5 MB, ≤10000 фото;
* version 1: без edits/view; 2+: strokes, crop, passes, pass_models, logo;
* points/width/erase/crop ограничены по контракту Python; pass_models по умолчанию `lama`;
* relative paths разрешаются от каталога сессии;
* view clamp/NaN defaults как Python.

Неподдерживаемое:

| Случай | Поведение |
|---|---|
| crop | `readOnly=unsupported_crop`, crop сохранён в модели, файл не перезаписывается |
| logo/logo template | `readOnly=unsupported_logo`, logo не теряется, не выполняется |
| pass model != lama | `readOnly=unsupported_model`, pass не выполняется |
| version 7/sdxl | readOnly |
| неизвестный/повреждённый JSON | `session_invalid` |

### B.2. Writer

Для поддерживаемых сессий (только lama, без crop/logo) пишется минимальная схема:
* version **2** без passes, **3** с passes;
* strokes, passes, pass_models;
* relative paths, selected, view, output_size;
* без пикселей/credentials.

Запись: temp в том же каталоге → mode `0600` → fsync → POSIX rename. Ошибка/read-only не трогает существующий файл. Тест: failed save оставляет байты исходного файла неизменными; mode 0600.

### B.3. Python → Native → Python

Python fixtures схем 1–7 (`/tmp` → container) прошли Native:

* v1/v2/v3: `readOnly=false`, сохранены; Python `load_session` читает 2 фото, strokes/passes `lama`;
* v4 migan, v5 logo, v6 template, v7 sdxl: `readOnly`, `saved=false`, original SHA unchanged;
* crop fixture: readOnly, save throws `session_read_only`.

Python output after Native save:

```text
v1 ok 2 photos; v2 strokes=1; v3 passes=1 models=('lama',)
```

## Часть D. Незакрытые пункты

* 5 mask-пикселей round-cap и sub-LSB RGB; визуальный паритет не заявлен.
* Replay/switch/cancel-во-время-replay проверен не полностью; текущий self-test проверяет eviction/replay, switch и cancel отдельно.
* Несколько больших фото с вытеснением/восстановлением не прогнаны; 384 MiB cache вмещает один 40 Мп результат (160 MB), два — 320 MB.
* UI open/save `.photoprep.json` не пройден вручную; core/CLI и Python fixtures проверены.
* Interrupted save проверен через failed-save-until-write/no-overwrite, не через kill посреди rename.
* History/session state не персистится между запусками, кроме явного session save.
* Нет native 40 Мп, 8/16 GiB, Intel/macOS14. Worker не XPC.

## Итог

Ключ кэша теперь учитывает SourceIdentity, последовательность рецептов и modelID; replay использует модель pass; undo сохраняет уточняющие штрихи; lifecycle не оставляет занятый слот при switch/stale; replay учитывает общий budget и освобождает display reference при eviction. Сессии читают схемы 1–7, сохраняют поддерживаемое в минимальной схеме 2/3 атомарно и приватно, не теряют crop/logo/unsupported проходы (read-only, без перезаписи), проходят Python→Native→Python fixtures, а reopen replay даёт побайтово тот же результат.

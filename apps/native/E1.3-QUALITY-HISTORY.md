# E1.3 — диагностика качества и накопительные проходы

**Дата:** 31.10.2026  
**Ветка:** `e1.3/quality-history`, от E1.2 `1c8a33e`.  
**Коммиты:** `6474939` (8-bit rounding + scale regressions), `4b2641e` (edit state/passes/cache/replay), `d62bbe2` (diagnostic tool), `6d3cb78` (cancel mask test), отчёт — этот коммит.

Python, окружение, веса и пользовательские данные не менялись. XPC не переписывался, новых моделей/FP16/crop/logo/export/sessions нет.

## Часть A. Диагностика качества: четыре комбинации входов

Одна и та же Core ML `LaMa-fp32.mlpackage` получала:

1. Python RGB + Python mask;
2. Native RGB + Python mask;
3. Python RGB + Native mask;
4. Native RGB + Native mask.

Сравнение — с Python/ONNX reference output, на одинаковых 512-тензорах. Dumps: astronaut/coffee/brick; Python `image512-python.npy`, `mask512-python.npy`; Native `image512-native.f32`, `mask512-native.f32`.

### A.1. До исправления RGB

| Фото | py RGB + py mask | nat RGB + py mask | py RGB + nat mask | nat RGB + nat mask |
|---|---:|---:|---:|---:|
| astronaut | max 0.0024 / mean 3.5e-5 | **9.53 / 0.377** | **16.99 / 0.0763** | **16.19 / 0.411** |
| coffee | max 0.0018 / mean 3.7e-5 | **13.18 / 0.313** | **4.49 / 0.0168** | **13.19 / 0.315** |
| brick | max 0.0016 / mean 1.7e-5 | **8.75 / 0.410** | **10.62 / 0.0647** | **11.02 / 0.426** |

max/mean — абсолютная разница в 0..255 units. `py+py` — шум Core ML vs ONNX, не ошибка препроцессинга.

Вывод до исправления: **Native RGB давал основной средний вклад** (mean 0.31–0.41), mask — меньший mean, но большой max на astronaut/brick. Объяснять всё LaMa было нельзя.

### A.2. Проверка 8-битного перехода

Python получает **8-битное** изображение после QImage scaling; Native интерполировал в fractional float и только потом делил на 255. Проверены три правила квантования Native RGB к 8 битам:

| Вариант | max vs Python RGB | mean | пикселей ≠ |
|---|---:|---:|---:|
| raw fractional | 0.00199 | 0.00095 | ~770 000 |
| **round / ties-to-even** | 0.00392 | **1.4e-5** | **~2 800** |
| floor | 0.00392 | 0.00190 | ~380 000 |
| trunc | 0.00392 | 0.00190 | ~380 000 |

Правило выбрано по эталону: **round to nearest, ties-to-even**. Затем тот же rounding проверен через Core ML:

| RGB + Python mask | astronaut | coffee | brick |
|---|---:|---:|---:|
| q_round | **2.90 / 0.0272** | **1.98 / 0.0210** | **1.15 / 0.0161** |
| q_floor | 14.65 / 0.594 | 16.01 / 0.592 | 14.02 / 0.564 |
| q_trunc | 14.65 / 0.594 | 16.01 / 0.592 | 14.02 / 0.564 |

Именно rounding, а не «фильтр масштабирования»: floor/trunc отвергнуты измерением. В Native добавлено `rounded(.toNearestOrEven)` после bilinear и до `/255`.

### A.3. После исправления

| Фото | nat RGB + py mask | py RGB + nat mask | nat RGB + nat mask |
|---|---:|---:|---:|
| astronaut | **2.90 / 0.0272** | 16.99 / 0.0763 | **17.24 / 0.0844** |
| coffee | **1.98 / 0.0210** | 4.49 / 0.0168 | **4.51 / 0.0270** |
| brick | **1.15 / 0.0161** | 10.62 / 0.0647 | **10.62 / 0.0657** |

После rounding:

* RGB-вклад по mean упал в ~10–15 раз;
* **mask остаётся главным max-вкладом** на astronaut/brick (5 пикселей round-cap);
* coffee mask почти не влияет (1 пиксель).

Native final после rounding:

| Фото | final max | final mean | >1 LSB |
|---|---:|---:|---:|
| astronaut | 13 | **0.0281** | 3 076 |
| coffee | 4 | **0.0112** | 92 |
| brick | 8 | **0.0222** | 2 431 |

До rounding было astronaut 13/0.083, coffee 13/0.056, brick 9/0.095. Средняя ошибка снизилась в 2.5–5 раз; max astronaut остаётся из-за mask.

### A.4. Большой контекст и регрессии масштабирования

2 Мп (2048×1536, context 1353):
* RGB 512 Native vs Python: **max 0, mean 0**;
* mask 512: **max 0, mean 0**;
* model max 0.00206;
* final max 1, 0 >1 LSB.

Добавлены регрессионные unit-тесты:
* upscale 16×12 → 512: все RGB после подготовки кратны 1/255 (8-bit transition);
* mixed scale 900×300: finite, mask 0/1, outside и alpha точны;
* downscale 1200×800: finite, mask 0/1, context 1200×800;
* context/scale/dilation cancellation и границы.

Всего **19 Swift tests** (было 16).

### A.5. Что осталось и что относится к LaMa

* Mask 512 astronaut/brick: 5 пикселей, coffee: 1 пиксель — край round-cap/antialias CGContext vs QPainter.
* RGB 512: max 1 code (0.00392), mean 1.4e-5; не >1 code после округления.
* Astronaut hair/face edge на 200%: чувствительность LaMa к 5 mask-пикселям, не отдельный RGB-дефект.
* Grass: размытие высокочастотной фактуры есть и в Python; это ограничение LaMa/домена, но Native не должен считаться «идеальным» на траве.
* Brick: final max 8 — тонкие швы восстанавливаются хорошо.
* Coffee: final max 4 — почти паритет.

Итог: **RGB-препроцессинг исправлен измеренно**; mask-растеризация остаётся единственным заметным Native-вкладом в max. Нельзя объявлять остаток только ограничением LaMa.

## Часть B. Накопительные проходы и история

### B.1. Модель состояния

Добавлены:

* `PhotoEditState` на каждый URL: `mask` для следующего прохода + `passes: [RetouchPass]`;
* `RetouchPass` — рецепт (id, strokes, timestamp), без пикселей;
* `PixelCache` — LRU результатов, бюджет **384 MiB**, ключ `photo#pass`;
* `passCount`, кнопка «Отменить проход», «Восстановить результат»;
* history UI: «Проходов: N».

Правила:

* успешный проход добавляет рецепт и очищает текущую маску для следующего прохода;
* следующий проход берёт **результат предыдущего** как source;
* ошибка/отмена не добавляют рецепт и **не очищают маску**;
* clear mask не удаляет passes/result;
* undo last pass удаляет последний рецепт, возвращает его маску и предыдущий результат;
* «До/После» — только display flag, рецепт не меняется;
* switch photo сохраняет/загружает mask+passes;
* cache может вытеснить пиксели; recipes остаются; replay идёт с оригинала последовательно.

### B.2. Self-test накопительных проходов

Реальный app-процесс, coffee + astronaut:

```text
E1.3 history: outside=yes clear=yes toggle=yes replay=yes switch=yes undo=yes
E1.3 history cancel mask kept=yes
```

JSON:

```json
{
  "pass1": true, "pass2": true, "outsideSame": true,
  "clearKeptResult": true, "toggleKeptRecipe": true,
  "replayRestored": true, "switchKept": true,
  "undoKeptOne": true, "passCountAfterUndo": 1,
  "cacheBytes": 1920000, "astronautPasses": 0
}
```

Проверено:

| Критерий | Результат |
|---|---|
| следующий проход с предыдущего результата | `outsideSame=true`; second pass вне mask2 побайтово равен first result |
| смена фото сохраняет маску/проходы | `switchKept=true`; astronaut passes=0, coffee passes=2 |
| clear mask не удаляет ретушь | `clearKeptResult=true` |
| undo pass возвращает маску | `undoKeptOne=true`, passCount=1, strokes непустые |
| «До/После» не меняет рецепт | `toggleKeptRecipe=true` |
| ошибка/отмена не потребляют маску | `cancelKeptMask=yes`; error path не очищает strokes |
| cache budget | 384 MiB; coffee 2 pass cache 1.92 MB |
| replay после eviction | `replayRestored=true` после `pixelCache.clear()` |

### B.3. Реальный UI

* после первого прохода панель показывает **«Проходов: 1»**, кнопку **«Отменить проход»**;
* повторный проход/undo pass доступны;
* UI screenshot: `work/e1.3-artifacts/e1.3-pass1.png`;
* функциональные проверки выше в основном self-test: ручной сценарий двух проходов с мышью не доведён до полного автоматического теста.

Ограничение: history — in-memory, без sessions/диска. Это соответствует исключению sessions из этапа.

## Часть D. Незакрытые пункты

* 5 mask-пикселей (astronaut/brick) и 1 (coffee); max astronaut 13.
* Ручной UI-сценарий двух/нескольких проходов и undo pass не автоматизирован полностью; self-test + UI pass count/button.
* History не сохраняется между запусками (sessions исключены).
* Replay/eviction проверены на coffee 600×400; для 40 Мп несколько проходов не тестировались, хотя cache 384 MiB вмещает один 40 Мп результат (160 MB), два уже 320 MB.
* Ошибка с изменением исходника проверена в E1.2; cancel-mask — в E1.3; произвольная ошибка worker с mask retention проверена кодом, не отдельным UI.
* Нет native 40 Мп, 8/16 GiB, Intel/macOS14.
* Worker остаётся self-exec Process, не XPC.

## Итог

Диагностика разделила вклад: **RGB 8-bit rounding был главной средней ошибкой**; mask round-cap — главный остаточный max. После округления final mean: astronaut 0.028, coffee 0.011, brick 0.022; big-context 2 Мп даёт exact RGB/mask. Накопительные проходы реализованы с per-photo масками/рецептами, cumulative source, undo-pass, bounded LRU cache и replay после eviction; self-test прошёл все критерии, UI показывает pass count и undo pass.

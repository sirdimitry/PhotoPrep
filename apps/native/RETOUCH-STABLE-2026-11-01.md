# Сохранение результата ретуши — 01.11.2026

## Актуальная сборка

`work/PhotoPrep-Native-v1-retouch-stable.app`

Release, arm64, ad-hoc подпись, App Sandbox, встроенная LaMa. Перед запуском нужно полностью закрыть старую сборку: одинаковый bundle ID может направить открытие в уже работающий процесс. Установленное приложение и открытая пользователем сборка не изменялись.

## Что исправлено

- Рабочий холст и кадрирование используют последний обработанный результат независимо от старого флага показа до/после.
- Новый штрих, отмена штриха, очистка маски и запуск следующего прохода не подменяют обработанную фотографию исходником.
- При исключении пикселей из LRU сохраняется самостоятельная ссылка на текущий видимый результат. После перехода на другую фотографию результат при необходимости восстанавливается по её рецепту.
- При отсутствии результата, который должен быть восстановлен по истории, исходник не показывается как якобы готовая фотография: выводится состояние восстановления с возможностью повторить его.
- Превью другой фотографии не используется для текущей выбранной фотографии.
- Маска и новый PNG-логотип остаются отдельными редактируемыми слоями. PNG не попадает во вход LaMa; окончательное объединение выполняется при экспорте.
- Кнопки и реализации перегенерации нет: начатые изменения отменены по просьбе пользователя.

## Диагностика в обычной сборке

Добавлен `retouch-events.json` в папке Application Support приложения. Он записывается и в Release, сохраняет последние 100 событий: время, начало/завершение обработки, число проходов и штрихов, наличие результата, стадию и код ошибки. Изображения и личные пути в него не записываются.

Обычный путь:
`~/Library/Containers/com.sirdimitry.PhotoPrep.Native/Data/Library/Application Support/PhotoPrep Native/retouch-events.json`

Журнал создаётся при новом событии редактирования/ретуши. Старые операции задним числом не восстанавливаются.
